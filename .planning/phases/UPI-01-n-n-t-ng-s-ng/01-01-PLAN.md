Dev dependencies: `@biomejs/biome` at 2.4.2 exact (keep the scaffold's pin — its generated

mismatch warning for no benefit), `prisma` at 7.10.0 exact, plus floating `@tailwindcss/turbopack`
at `^4`, `@types/node` at `^22`, `@types/react` at `^19`, `@types/react-dom` at `^19`, `dotenv`
at `^18`, `tailwindcss` at `^4`, `tsx` at `^4.23.15`, `typescript` at `^5`, `vitest` at `^5.0.3`.

Two of those deserve their reasons recorded, because both are counter-intuitive:
- `prisma` must be written as `7.10.0`, because the registry `latest` tag currently resolves to
  `8.0.0-rc.20`. A caret or a bare install name pulls a release candidate whose generated client
  is incompatible with the pinned `@prisma/client` runtime.
- `@types/node` must be raised from the scaffold's `^20` to `^22` BEFORE Vitest is installed.
  Vitest 5 declares an optional peer on `@types/node` `^22 || >=24`, and installing it against
  `^20` fails resolution outright. Do not reach for a legacy-peer-deps escape hatch; the bump is
  the correct fix and pnpm is stricter here than npm.

Add the scripts block: `dev` runs `next dev`; `build` runs
`prisma generate && prisma migrate deploy && next build`; `start` runs `next start`;
`lint` runs `biome check`; `format` runs `biome format --write`; `test` runs `vitest run`;
`seed` runs `tsx prisma/seed.ts`.

The `build` script is the INFRA-04 mechanism — migrations apply automatically on every deploy
because Vercel runs this script. Keeping it in `package.json` rather than `vercel.json` or the
dashboard means it behaves identically locally and on Vercel, and it needs no manual setup step.
`prisma generate` must stay first: Prisma 7 removed the postinstall hook, and the generated
client lives under `src/` (not `node_modules/`), so every clean build starts without it.

Add an `engines` field requiring Node `>=22.12`. That floor is set by Vitest, which is the
strictest of the three constraints, and it tells Vercel which runtime to select.

Then install with pnpm and commit the resulting `pnpm-lock.yaml`.

<task type="auto">
  <name>Task 3: Toolchain and deploy configuration files</name>
  <files>tsconfig.json, biome.json, vitest.config.mts, vercel.json, .env.example, .gitignore</files>
  <action>
Six config files. Each closes a specific known failure.

`tsconfig.json` — keep the scaffold's `"strict": true` (this is what satisfies INFRA-01) and add
`"noUncheckedIndexedAccess": true`. That flag is a locked user decision: Phase 2's money-splitting
algorithms are dense with array indexing, and enabling the flag after that code exists means
repairing a backlog of violations instead of never writing them.

`biome.json` — keep the scaffold's config and add a `files.includes` array that excludes
generated and build output: include `**`, and negate `node_modules`, `.next`, `dist`, `build`,
and `src/generated`. Without the last negation Biome reports diagnostics against the generated
Prisma client, which is machine-written and not ours to fix.

`vitest.config.mts` — the extension must be `.mts`, not `.ts`: `package.json` has no
`"type": "module"`, so a `.ts` config makes Vite warn that it is loading ESM as CommonJS. Config
body sets `resolve.tsconfigPaths` true, `test.environment` to `node`, and `test.include` to
`src/**/*.test.ts`. Vite 8 resolves tsconfig path aliases natively, so do NOT add
`vite-tsconfig-paths` or `@vitejs/plugin-react` — both are redundant here. `node` is the right
environment for this phase and Phase 2 (pure logic, no DOM); add jsdom only when a component
actually needs rendering.

`vercel.json` — two keys only: the `$schema` pointing at `https://openapi.vercel.sh/vercel.json`,
and `regions` set to the single-element array `["sin1"]`. `sin1` is Singapore
(`ap-southeast-1`), the same region the Neon database will be created in, so function-to-database
latency stays intra-region. Hobby plans may select exactly one region, and this is one. Declaring
it here rather than in the dashboard removes a manual step and survives a project re-import.
Do NOT add a `buildCommand` key — `package.json` already owns it, and duplicating it creates two
places to edit.

`.env.example` — committed template, no real secrets. Document each variable with a short
comment saying where its value comes from: `DATABASE_URL` is Neon's pooled string (hostname
contains `-pooler`) used by the app at runtime; `DATABASE_URL_UNPOOLED` is Neon's direct string
used by every Prisma CLI invocation; `AUTH_SECRET` comes from `npx auth secret`;
`AUTH_GOOGLE_ID` and `AUTH_GOOGLE_SECRET` come from the Google Cloud Console OAuth client;
`AUTH_TRUST_HOST` is set to true so Auth.js trusts Vercel's forwarded host; `ALLOWLIST_EMAILS`
is the seed input in `email[:label]` comma-separated form.

Record one non-obvious fact in the `DATABASE_URL_UNPOOLED` comment: it is required for EVERY
`prisma` CLI command including `prisma generate`, which never touches a database. The config
loader resolves it eagerly and throws when it is absent, so a missing value fails the build with
a message that mentions neither Vercel nor migrations and is easy to misdiagnose.

`.gitignore` — append to the EXISTING file, never replace it. Two additions. First, a negation
for the env template: the scaffold's rule ignores every `.env*` path, which silently swallows
`.env.example` too, and that file is required to be committed. Second, ignore `/src/generated`,
since the Prisma client is regenerated on every build and must not be committed.
  </action>
  <verify>
    <automated>node -e "const t=require('./tsconfig.json');if(!t.compilerOptions.strict)throw new Error('strict off');if(!t.compilerOptions.noUncheckedIndexedAccess)throw new Error('noUncheckedIndexedAccess off');const v=require('./vercel.json');if(JSON.stringify(v.regions)!=='[\"sin1\"]')throw new Error('region not sin1');if(v.buildCommand)throw new Error('vercel.json must not duplicate buildCommand');const b=require('./biome.json');if(!JSON.stringify(b.files).includes('src/generated'))throw new Error('biome must exclude src/generated');console.log('config ok')" && test -f vitest.config.mts && grep -q 'tsconfigPaths' vitest.config.mts && for v in DATABASE_URL DATABASE_URL_UNPOOLED AUTH_SECRET AUTH_GOOGLE_ID AUTH_GOOGLE_SECRET AUTH_TRUST_HOST ALLOWLIST_EMAILS; do grep -q "^$v\|^# *$v" .env.example || { echo "MISSING $v in .env.example"; exit 1; }; done && grep -qF '!.env.example' .gitignore && grep -q 'src/generated' .gitignore && git check-ignore -q .env.example && { echo 'FAIL: .env.example still ignored'; exit 1; } || echo 'env.example committable' && pnpm lint && pnpm tsc --noEmit</automated>
  </verify>
  <done>tsconfig has strict and noUncheckedIndexedAccess; biome excludes src/generated; vitest.config.mts exists with tsconfigPaths and no redundant plugins; vercel.json pins sin1 and declares no buildCommand; .env.example names all seven variables and is NOT git-ignored; .gitignore ignores /src/generated; `pnpm lint` and `pnpm tsc --noEmit` both pass.</done>
